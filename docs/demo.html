演示指南

当前版本的一条真实模型 UI 路径：播放 33.32 秒录屏 · 原始 WebM · 消息、回执、版本与费用。无声、原速连续录制，无剪辑或答案回放。画面中的“模拟业务系统”始终可见；真实调用官方 deepseek-flash，企业状态与员工恢复反馈均为合成数据，没有连接真实 Okta。

讲解顺序

  1. 0–5 秒：身份与输入。 Alice 登录、新建聊天，用全新表述描述自己在公司电脑上的 Okta 锁定。新输入直接进入模型，不携带案例编号。
  2. 5–17 秒：查证与操作。 Agent 查询账号和政策，执行一次普通本人账号解锁，保存实际模拟收据；页面仍等待员工重试，未凭解锁就结案。
  3. 17–29 秒：恢复反馈。 开发者输入合成反馈“现在能进去了”，Agent 再次查询后更新为已确认解决。两个阶段保留在同一聊天。
  4. 29–33 秒：持久状态。 页面重载，从历史重新打开该聊天，消息和收据仍在。审批、影响确认与交接可结合已有证据讲解；本录屏只展示账号正常路径。

本次有 2 个 completed live_agent 运行、7 次模型请求（4+3）、4 次非终结工具（3+1）、1 次解锁收据、0 个事件错误和 0 个浏览器脚本错误。两个运行保存的 prompt_version 均为 helpdesk-2026-11-02-v7-matched-followup，不只是检查磁盘上的提示词。运行代码与冻结 baca519 的哈希一致；录制时 Git HEAD 为 abcaf05（后续仅文档/证据差异）。最终截图保留原始回复，仍有账号重复与重复结束邀请，不能称为自然表达已完全解决。

面试现场输入

按根 README启动后，新建聊天，请演示者自行输入问题并按当前追问补充事实。观察单独目标、来源、未解决状态和实际收据；自由文本不是效果凭证。不要为配合演示声称真实系统已经恢复。
