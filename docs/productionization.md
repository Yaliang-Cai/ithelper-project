# 生产化说明

当前是单机模拟原型。先接只读数据和低风险操作，再逐步接入生产授权；每一步都以可审计的结果决定是否扩大范围。

| 部分 | 接入方式与边界 |
| --- | --- |
| Slack / Teams | 增加消息与交互卡片适配层，复用现有业务 API；把员工、会话、问题和外部消息关联。去重重复事件，审批与确认仍由明确操作触发。 |
| SSO 与权限 | 用企业身份提供方替换演示登录，映射稳定员工 ID、部门和角色。平台账号与企业身份绑定，不能从聊天文本取得身份或审批权。业务权限检查保留在执行层。 |
| 企业数据 | 将目录、状态、KB 和变更查询接到受限服务账号；按员工访问范围过滤结果，记录来源、版本和查询时间。凭据保存在密钥管理服务，不进入模型上下文。 |
| 真实写操作 | 逐项确认供应商幂等机制与回查接口。外部操作无法与本地数据库一起提交，需保存外部请求 ID、查询实际结果并对账；结果不确定时不盲目重试。 |
| 审计与运维 | 关联消息、问题、工具调用、批准、操作收据和版本，限制日志访问并脱敏。观测延迟、失败类型、转人工率、错误结案、重复动作和每次处理成本，设置保留期限及告警。 |
| ServiceNow 交接 | 创建包含事实、假设、尝试、证据和未答问题的工单，保存工单号与负责团队。接口失败保留待同步状态，不向员工声称交接成功；回调通过事件去重处理。专家补充后是否恢复 Agent，需有明确的负责方切换和重新验权。 |
| 存储与运行 | 多副本前迁移到共享事务数据库和可靠事件队列，保留版本检查、租约及幂等约束。测试重启、重复消息、供应商超时和操作结果回查。 |

上线顺序：小范围只读诊断 → 经批准的低风险操作 → 生产权限及完整人工接续。每阶段补充真实案例的脱敏回放和 IT 专家抽查，保留停止自动写入的开关。SSO、平台接入、外部对账和真人接续均未在当前原型中实现。
