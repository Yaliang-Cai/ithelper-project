# 验证结果与限制

2026-11-02。项目已具备可运行的员工聊天、模拟业务操作、审批、确认与交接。程序边界的验证比自然对话效果更充分；目前可作为 take-home 原型交付，尚不能证明大多数新问题都能稳定解决。

## 原题要求与实际实现

| 要求 | 当前实现 | 依据与局限 |
| --- | --- | --- |
| 对话诊断与多步工具调用 | 单 Agent 的理解阶段和动态工具循环；根据结果继续查询或追问 | `app/agent.py`；真实对话保留工具轨迹，仍发生协议和问题理解错误 |
| 多源推理 | KB、历史、目录、状态变更、政策五类来源 | `data/`、`app/retrieval.py`；同源小样本检索对照，不代表真实企业知识库 |
| 状态与记忆 | 独立问题项、观察、证据、操作和当前聊天历史持久化 | `app/domain.py`、`app/context.py`；不检索个人其他聊天，长历史可能容量停止 |
| 解决、审批与升级 | 普通本人解锁、目录授权；VPN 确认；生产权限审批；保存交接 | `app/tools.py`；模拟系统实际变更，交接没有连接真人 |
| 可靠性与权限边界 | 事务内核对范围、版本、批准与确认；幂等和中断恢复 | Domain/API/Worker 测试；不能保证模型正确理解所有自然语言 |
| 评估与工程思考 | 案例预期、用户模拟、程序断言、AI 评分、费用与执行记录 | `evals/`；合成样本，同模型评分，无独立专家标注 |

## 0.1.3：多账号录屏与错误定位

试录暴露多问题收尾的错误信息缺少范围：拒绝 Okta 结案时只说缺少应用检查，模型转而重复查询 Salesforce，两次事件以 `NO_PROGRESS` 结束。现有验收错误补充所属问题、类型和服务，缺少服务状态时说明对应查询工具；验收条件未放宽。

新增回归先重现失败，再验证多项更新整体回滚、版本保持，以及补正确证据后重提成功。另有累计预算提高仍保留旧费用、录制不得截断在途事件或未结费用的回归。最终 221 项通过。

修复后重新录制三账号、多轮和审批继续处理；8 个事件完成，48 次模型请求。一次新鲜账号证据不足的拒绝明确指向 Okta，模型随后补查并完成收尾。该次结果不能证明普遍稳定；[演示说明](demo.md)保留失败、改动与实际消息的链接。预算经确认从 US$3 提高到 US$4，仍使用原账本，本轮新增费用未超过获准的 US$1。

## 0.1.2：验收与统计修正

- 员工报告问题复发后，旧的恢复反馈曾可能再次被用于结案。现在复发症状会使较早反馈失效，新的明确恢复反馈仍可通过验收。
- 同一问题再次执行解锁后，追加另一种指导曾沿用首次操作的反馈时间。现在以最近实际操作或尝试为准，要求该问题有更新的失败反馈。
- 报告生成器曾把一次预留前被预算阻止的调用计为实际请求。现在分开统计尝试与账本请求，并按原批次固定历史结果分母，后续定向测量另列。

四项新回归在修复前失败、修复后通过；完整离线套件 218 项通过。修复限于现有验收与统计逻辑，没有新增服务、审批层或业务功能。0.1.2 检查没有新增付费模型调用；当时引用的实模结果对应该次修复前代码。后续 0.1.3 录屏另列。

## 仍然存在的问题

1. 追问与结构化问题有时不一致。旧 D05 只问页面范围却记录了起始时间问题；新版对话覆盖了时间、页面和同事情况的续问，但仍有重复询问已经确认信息的问题。
2. 回复仍冗长。新版出现英文 KB 原文、过强的诊断措辞，以及把 Data 看板正常扩展为其他看板没有报错；没有充分证据支撑这部分语义。
3. v7 的正式定向复测只有两个已知案例，另有旧录屏和本次多账号演示。重复次数不足；未覆盖外部事故恢复后的续问，没有最终版本的完整盲测。
4. 程序能阻止不满足权限条件的操作，却不能证明诊断、指代和交接解释在语义上正确。同模型评分出现过误判，因此保留原文并单列无效评分。

优先补同一版本的多轮续问、失败复测与重复覆盖，再考虑新功能。生产化另需真实身份与业务接口、外部操作对账、专家接续和独立评审。
