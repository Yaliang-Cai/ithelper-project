# 验证结果与限制

当前可以运行员工聊天、模拟操作、审批、确认与交接。程序边界的验证比自然对话效果更充分；现有证据不足以说明大多数新问题都能稳定解决。

## 验证范围

| 验证 | 结果 | 依据与局限 |
| --- | --- | --- |
| 程序回归 | 221 项通过 | 身份隔离、政策、审批确认、幂等、恢复、状态与评测器；模型采用替身。见 [CI](https://github.com/Yaliang-Cai/ithelper-project/actions/workflows/checks.yml) |
| 案例结构 | 31 个变体有效，30 个设计槽位 | 五类场景与错误路径均有案例；不等于 31 个实模对话全部成功 |
| 最新真实模型录屏 | 7 条员工输入和 1 个审批事件，8 次回复；一次解锁、两次授权 | 8 个事件完成；Salesforce 等待外部恢复。业务与员工反馈为合成 |
| v7 定向复测 | D05、D09 的程序目标满足，无事件错误 | 两个已知案例各一次；等待外部恢复后的续问未验证 |
| 历史实模测量 | 63 次场景测量，另有 3 次特殊回归 | 多个版本的探索结果，不能当作当前版本成功率 |
| 历史检索对照 | 有答案查询：关键词 26/35，混合 35/35；无答案查询均 5/5 | 小规模同源样本，未证明普遍端到端收益 |

最新录屏对应运行提交 `bd41762`，提示词 v7。8 个事件的后端处理耗时为 6.1–24.3 秒，48 次模型请求，估算 US$0.220164301，embedding 另计。这个时长不含员工思考和审批等待，不代表完整问题平均解决时长。费用按 token 保守估算，不是供应商账单。

## 失败与改进依据

| 观察到的问题 | 修改 | 验证与剩余限制 |
| --- | --- | --- |
| 多问题收尾时，错误没有指出缺证据的目标，模型重复查询另一服务 | 验收错误附带当前问题、验收类型和服务范围 | 回归验证整批回滚与补证据重提；新录屏中模型能按目标补查。仍只是一条恢复轨迹 |
| 用户报告复发后，较早的恢复反馈可能再次用于结案 | 新失败或纠正使较早恢复反馈失效 | 程序回归通过，未完成各类复发的同版本实模重复测量 |
| 重复操作后，下一种指导沿用首次操作时间 | 以最近操作或尝试为反馈门槛 | 程序回归通过，避免未观察结果就追加处理 |
| 报告把预留前被预算阻止的调用算成实际请求 | 分开统计尝试与账本请求，固定历史批次分母 | 合成批次回归证明后续评测不会改变历史截止值 |

多问题试录保留了两次 `NO_PROGRESS`，没有改成成功。新录屏仍可看到范围错误、证据不足和版本冲突被拒绝后继续处理。[试录原文](evidence/demo-multi-20261102/pre-fix.json)与[新录屏记录](evidence/demo-multi-20261102/walkthrough.json)可直接核对。

## 当前限制

1. 自然表达仍有偏差：重复追问、冗长、英文 KB 原文和过强诊断措辞。新录屏最后还把“Data 看板正常”扩展为其他看板没有报错，超出了员工反馈。
2. 最新录屏没有覆盖 VPN 确认、人工交接和外部事故恢复后的续问。同版本的场景广度与重复次数不足，没有完整的新问题盲测。
3. 验收类型仍由模型选择。录屏的生产库问题使用了 `application_recovery`；虽然当次完成授权并回查，该类型只检查应用恢复所需的反馈和服务状态，没有强制检查精确权限。资源目标与验收类型需要在程序中绑定。程序校验也不能证明所有指代、诊断与回复语义正确；用户模拟和语义评分同源，没有真人专家评价。
4. 没有企业 SSO、真实业务接口、真人接续或多副本部署验证。当前 SQLite 原子事务不能证明外部系统操作可靠性。

后续先补同版本的失败复测和自然多轮输入，再做独立 IT 评审。详细历史数字见[历史测量](evaluation-report.md)，定向测量见[迭代结果](delivery-iteration-result.md)。
