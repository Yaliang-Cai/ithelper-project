## 试录发现与局限

此前试录中，模型同时提交 Okta 结案和 Salesforce 等待，程序只返回“缺少当前应用检查”，未指出失败的问题。模型连续查错对象，两次事件以 `NO_PROGRESS` 停止。[原始失败记录](evidence/demo-multi-20261102/pre-fix.json)保留不改。

修复仅补充错误所属的问题、验收类型和服务；缺少服务状态时说明对应查询工具。没有放宽验收条件。新增真实数据库回归验证整批回滚、版本保留和补证据后重提，完整套件 221 项通过。新版录屏中，另一处缺少账号检查的拒绝也带上问题范围，模型随后查询了正确账号并继续完成。这是一次实际恢复过程，不是对模型稳定性的统计证明。

仍能看到回复偏长、已经确认的信息被重复询问、英文 KB 原文直接出现在中文回复，以及“基本排除电脑问题”等证据不足以完全支持的措辞。最后一句还把“Data 看板正常”扩展为其他看板也没有报错，超出了员工反馈范围。状态和操作可审计，语言含义仍需评测。VPN 确认、交接和外部事故恢复后的续问不在新版录像内。

## 提交与本地记录

原题要求可运行仓库、README 和面试演示，允许录像，也会现场输入新问题。没有要求预置员工聊天历史。仓库包含合成源数据、评测案例和上述演示证据；`runtime/` 中的业务数据库、个人本地聊天、费用账本与密钥不进入提交包。首次启动会建立本地业务数据，评审可以直接聊天。

提交入口是仓库根目录 README；本页播放器用于观看视频。`docs/index.html` 只是详细文档的本地阅读入口，不是单独提交项。旧版 33 秒录屏仍保留在[历史目录](evidence/demo-v7-recording/index.html)。

## 可选复现工具

观看已有视频无需安装录制工具。重录需要 Playwright，且会产生新费用：

```powershell
python -m pip install playwright
python -m playwright install chromium ffmpeg
# 离线检查
python scripts/verify_browser.py
python scripts/verify_ui_states.py
# 交互式录制；输出目录必须尚不存在
python -m scripts.record_walkthrough --output runtime/my-new-demo --max-cost 0.20
```

程序打印命令目录后，按 `001.json`、`002.json` 顺序写入操作，例如 `{"op":"login","actor":"alice.sales"}`、`{"op":"new_chat"}`、`{"op":"send","text":"Okta 提示账号锁定"}`。每一步先读取相应 `results/` 文件和实际回答，再发送下一步。其他操作见脚本头部说明；最后发送 `{"op":"finish"}`，等待在途事件和费用结算后生成视频与 JSON。

每次录制使用独立业务库，费用仍记入原账本。`--max-cost` 是本次预留增量上限，也受项目总上限约束；预算不会因新建业务世界而重置。
