Employee IT Helpdesk Agent

面向员工的 IT 支持原型。员工直接描述问题，Agent 查询资料、补充询问、执行允许的操作，并跟踪每个问题的结果。企业数据与业务系统为模拟环境；模型调用、登录、审批、状态变更和操作记录实际运行。

HTML 阅读版 · 演示视频与账号 · 验证结果 · 生产化说明

问题与范围

常见 IT 问题的耗时往往在信息收集、系统查询和反复沟通。本项目让员工在一个聊天中完成这些步骤；超出自动处理范围时，保存已调查的上下文再交接。

场景 当前处理范围
账号登录 查询账号与服务状态，解锁本人的普通锁定，继续确认登录结果；安全停用等问题交接
应用缓慢 对照地区事故、发生时间、影响范围和知识库，提供适用步骤或等待原因
VPN 断连 询问网络环境，检查会话；重置前取得员工对中断影响的确认，随后观察与验证
软件与数据权限 标准目录只读权限按政策开通；生产库只读权限需精确资源审批；不提供管理员或写权限
跨系统问题 联合查询依赖、变更和历史，保留假设与反证，必要时交接给对应团队

成功以具体问题的验收结果为准。执行了操作不等于体验已经恢复；一个问题完成也不会自动关闭其他问题。审批、等待外部恢复、已交接与已解决分别记录。交接保存目标、已查事实、假设、尝试结果、证据、未答问题和接手团队，员工无需重新描述；当前不连接真人或 ServiceNow。

为什么使用 Agent

FAQ 可以提供操作说明，却无法仅凭一次检索判断当前账号是否锁定、事故是否匹配、是否需要审批，以及操作后是否仍有问题。这里由单个 Agent 根据新消息和工具结果选择下一步，程序限制允许执行的操作与停止条件。调查顺序不预设为固定流程。

架构与取舍

员工聊天 / 审批 / 确认
        ↓
持久事件 → 消息理解 → 工具调用循环 → 回复、等待或交接
                       ↑     ↓
                  当前上下文与证据
                             ↓
                     业务校验与模拟系统

FastAPI 提供 API 和原生网页，SQLite 保存聊天、业务状态与执行记录。模型先提出结构化的问题和反馈解释，再选择工具调查；业务层校验记录和动作。两阶段便于区分理解错误与执行错误，增加了调用成本；未做对照实验证明准确率更高。

上下文由程序装配，包含当前身份、各问题状态、审批与确认、已有尝试、用户反馈和近期证据。问题关联只用于共享线索，不传播“已解决”结论。每轮最多 10 次模型请求、12 次非终结工具调用、120 秒；必需上下文超限时停止并保留进度。

身份来自已登录会话。业务事务核对操作范围、当前政策和批准记录，并将模拟业务变更与收据一起保存。重复请求复用结果；执行结果不确定时先查记录。API 处理身份与请求来源，业务层集中处理操作条件。

选择单 Agent、SQLite 和本地模拟系统，是为了把调查、动作和状态变化放在一条可检查的链路里。当前没有多 Agent、跨聊天个人记忆、真实企业接口或专家回流。模块职责见系统设计。

数据

来源 内容 用途
知识库 22 篇操作与排查文档 提供适用步骤，区分当前、过期和不适用方案
历史记录 12 条已处理案例 提供相似经验，不作为当前根因证明
用户目录 6 个账号及部门、地区、设备、权限 确定员工范围与适用条件
系统状态 8 个服务、2 个事故、2 个变更、2 条依赖 对照当前影响范围与跨系统关系
政策与资源 12 条政策、5 个精确资源 决定哪些操作可直接执行、需要确认或审批

KB 和历史使用关键词与向量混合检索；身份、状态和权限按结构化字段查询。全部数据为合成，包含无关事故、旧文档和相似但不适用的案例。

运行

需要 Python 3.12+，以及 DeepSeek、SiliconFlow 的独立 API Key。LLM 固定为官方 deepseek-flash，embedding 为 BAAI/bge-m3。正常聊天需要网络和可用模型额度；embedding 不可用时明确降级为关键词检索。

Windows PowerShell，在仓库根目录执行：

py -3.12 -m venv .venv
.venv/Scripts/python.exe -m pip install -e '.[dev]'
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
# 编辑 .env，填写 DEEPSEEK_API_KEY 和 SILICONFLOW_API_KEY
powershell -ExecutionPolicy Bypass -File scripts/run_local.ps1

macOS / Linux：

python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
test -f .env || cp .env.example .env
# 编辑 .env，填写两把 API Key
.venv/bin/python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000

打开 http://127.0.0.1:8000/ 。员工账号为 alice.sales、bo.remote、chen.data、dana.platform；审批账号为 pat.approver，调试账号为 dev.debug。演示密码均为 DemoPass123!。审批时可用另一个浏览器会话登录，也可以退出后切换账号。可直接输入新问题，无需案例编号。

首次启动会初始化合成业务数据。聊天保存在本地，关闭页面或重启后可以恢复；在途事件可能需要等待租约到期。密钥、运行数据库和本机聊天历史不包含在仓库中。

LLM_BUDGET_USD 控制累计估算额度，默认及允许上限为 US$4。请求前预留费用，超过额度停止新增调用。业务库位于 runtime/business.sqlite，固定费用账本为 runtime/usage.sqlite。如需重置业务，先停服务，再运行 .venv/Scripts/python.exe -m scripts.demo_reset；费用账本不会随业务重置。

评估与结果

.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m evals.runner validate

macOS / Linux 使用 .venv/bin/python 执行相同模块。

验证 已有结果 解释范围
程序回归 221 项通过 身份隔离、审批确认、幂等、恢复、多问题状态和评测器；模型使用替身
案例结构 31 个变体有效，对应 30 个设计槽位 覆盖五类场景及模糊、冲突、越权、失败情况；不等于全部对话成功
最新真实模型演示 3 个账号、7 条员工输入、8 次回复；一次解锁、两次授权 8 个事件完成；Salesforce 保持等待外部恢复，没有误记为解决
历史模型测量 63 次场景测量，另有 3 次特殊回归 来自多个版本，保留成功和失败，不能合并成当前版本成功率

评测用固定业务事实和预期结果检查动作与状态，使用规则及模型模拟自然员工，并由同一模型辅助评价回复和交接质量。没有真人盲测，也没有独立模型交叉评分。评估设计、验证结果与限制和 GitHub CI提供依据。

一次多问题试录中，校验错误没有说明缺证据的是哪个问题，模型持续查询错误对象。修复仅补充问题与服务范围，保留验收条件，并增加整批回滚和补证据重提的回归。原失败记录与修复后录屏均保留。复发后旧反馈失效、操作重试和交接去重也有针对性测试。

限制与下一步

自然对话仍会出现重复追问、回复过长、英文知识库原文和证据不足的确定措辞。最新演示未覆盖 VPN 确认、人工交接及外部事故恢复后的续问，不能据此证明五类场景均稳定解决。长聊天受上下文容量限制；模拟系统无法验证真实企业 API 的一致性与权限语义。

下一步优先做同版本的多轮重复评测，补失败路径和新问题输入，请 IT 人员审核诊断与交接质量，再接入真实系统。Slack/Teams、SSO、审计和 ServiceNow 的接入顺序及边界见生产化说明。
